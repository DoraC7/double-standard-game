# 推薦視窗回歸檢查

先依 [全站冒煙檢查](arcade-smoke-qa.md) 啟動網站。每次改首頁推薦流程時執行；不需登入。

1. 桌面 1280×900 按「幫我選一款」：視窗有名稱、圖片、描述、分類來源與「就玩這個」。以 Tab／Shift+Tab 巡覽，焦點可見且留在視窗內。
2. 按「再選一次」：有多個候選時不重複上一款；焦點保持在重抽按鈕，Play 的文字替代名稱與連結對應新遊戲。用螢幕閱讀器確認只簡短通知一次新遊戲名稱，不重讀整張卡。
3. 分別使用 Escape、右上關閉及視窗外背景關閉；每次都可重新開啟，關閉後焦點回到開啟按鈕。點視窗內容不應關閉。
4. 每個分類都試推薦，尤其「學點新東西」：名稱不含 undefined，推薦符合目前分類。「就玩這個」確實打開該款，返回首頁可重開。
5. 320×568 窄手機、844×390 及 568×320 短橫向尺寸重複開啟與重抽。在視窗內向下捲動可到主要按鈕，按鈕完整可點；關閉按鈕可達，不發生橫向溢出。只用鍵盤也可 Tab 到 Play 並自動捲入可視範圍。
6. 在系統開啟減少動態效果（或開發工具模擬 prefers-reduced-motion: reduce），重開／重抽：圖片沒有揭示與搖動動畫，操作仍正常。
7. 舊瀏覽器沒有 dialog API 時，按推薦應直接進入符合分類的遊戲，不留下空白視窗。若需在現代瀏覽器模擬，可在開發工具停用 JavaScript、重載，在 Sources 的最後一段首頁腳本開始處設中斷點，再啟用 JavaScript 重載；暫停時於 Console 執行 `HTMLDialogElement.prototype.showModal = undefined; HTMLDialogElement.prototype.close = undefined;` 後繼續。這只改本次頁面，正常重載即還原；自動化瀏覽器也可在載入前注入同樣設定。不要改正式網站原始碼。

記錄日期、瀏覽器與版本、尺寸、閱讀器（未測請標明）、逐項結果。Node 測試不能證明實際螢幕閱讀器播報或短畫面可用性。
